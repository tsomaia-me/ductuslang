## The five pins + two notes

1. **No-execution-constructs doctrine** (new 015-family entry + §13.1 principles mirror): no thread, task, future, goroutine, or any execution-resource construct exists in Ductus source, ever. Execution resources are backend concerns, invisible behind the two doors: behaviors (pure compute — schedulable anywhere) and effects (the world boundary — fulfilled by whomever). Concurrency-of-waiting is the effect system; there is nothing to add.

2. **The as-if parallelism law** (new 023-family entry + SPEC §13.10.3 + §14 mirror): a backend may evaluate dependency-independent per-commit DAG nodes concurrently, provided the observable outcome — values, trace, hook order — is identical to sequential evaluation in the committed total order (the composed tiebreaker order). Pure law, no capability advertisement: the capability-negotiation surface exists for observable powers; invisible parallelism has nothing to negotiate.

3. **Behavior-internal parallelism note** (sibling entry or same-family, implementer-facing, normative-as-latitude): a behavior's internal evaluation strategy — including data-parallel execution of a pure body and parallel reduction of a fold's combine tree (log-depth, independent subtrees) — is implementation latitude with no observable surface. Stated explicitly so implementers know parallelism-by-purity is out of the box, not an open design question.

4. **The `compute` builtin effect** (new 031-family entries + SPEC §13.19 section): a language-level builtin effect for heavy pure compute. Shape: `r = args |> compute(pure_fn)`; desired: the bound inputs; observed: `result: Option[Out]` (None until ready) + `in_flight: bool`. Fulfilled BY THE RUNTIME ITSELF — no host reconciler required (the "outside world" is a worker pool the runtime owns); hosts may override per capability. Lifecycle rides the standard effect hooks: gate-off → suspend → in-flight run CANCELLED; input change → update → stale run cancelled, fresh dispatched; teardown cancels. Coalescing: latest-wins — a stale run's result is never delivered after a newer dispatch (value-change semantics). Results enter as ordinary runtime-write-class inputs: timing relative to commits is nondeterministic, the same accepted class as any effect (the rule of thumb, stated: if the trace must be deterministic, do not offload — use @deferred or stay in-commit). Name `compute` (owner-seen in examples; veto-able).

5. **`deferred` — a first-class cell kind** (OWNER REVISION 2026-07-20, superseding the @deferred directive spelling; rationale: the recurrent precedent — temporal semantics are kinds, and no directive alters a read's freshness contract). Declaration form mirrors derived: `deferred spectrum: f32[512] = fft(samples)`. Joins the declaration keywords, the no-source-write kind enumeration, the kind/channel taxonomy (a value channel in the cell T umbrella), the IR cell-kind set, and RequiredCellKind (admitted as a trait required cell, mirroring derived); REJECTED inside effect desired:/observed: blocks in v1 (named diagnostic). Timing semantics unchanged from the original pin (new 016-family + 023-family entries + GRAMMAR DeferredDecl): a `deferred` cell evaluates OFF the driving context with commit-N snapshot inputs and publishes at EXACTLY commit N+1 — the structural one-commit shift, deterministic (the sequential value stream shifted one commit; kin of the recurrent's one-commit delay, cite the delay-element law's section). If unfinished when N+1 publishes, N+1 waits at the barrier. Chains pipeline (one stage per commit). Inherited semantics stated: gating freezes it (no evaluation while frozen; Model B); reload swaps its behavior by hash and discards any in-flight run; a trap in it is an ordinary evaluation trap of the commit it publishes in. The kind is legal wherever `derived` declares (module level, node/wire bodies); deferral of recurrents/streams/gates does not exist, and predicate/combiner positions never admit it.

6. **Multi-graph doctrine trio** (new 027-family entries + SPEC §13.14 mirror): (i) one driving context per graph, always — multi-graph composition never means shared memory; (ii) cross-graph communication is value-only and materialized per the existing host-boundary materialization law — no Handle/Portal ever crosses a graph boundary; (iii) any future cross-graph bridge is effect-shaped — an effect, never a new construct class.

7. **Bridge future-capability note** (SPEC, explicitly NON-NORMATIVE, adjacent to the doctrine): the anticipated shape — `bridge_out("topic")` / `bridge_in("topic")` effect pair, streams as the inter-cadence carrier, gate-policy backpressure on the receiving side, location transparency (in-process / IPC / network as backend capability, program text identical). Discovery, delivery guarantees, and cross-reload schema evolution are named as the deliberately-open questions deferred to the host era (M6). The note exists so the direction is on record without minting law.

## CLOSED (owner, 2026-07-20: "clear. and settled. execute")

Additional settled details from the closing discussion, binding on execution:
- Staged-work law: a completed deferred evaluation is staged work; the runtime surfaces staged-work presence to the host through the same surface as queued writes, so event-driven hosts can schedule the next commit on readiness. Metronomic hosts need nothing — the result lands at the next tick.
- Gate interplay: a gate closing over a deferred cell cancels its in-flight run (no publication, no barrier); the gate-open snap DISPATCHES a fresh deferred run (landing at +N) rather than evaluating synchronously — the frozen value serves until it lands.
- The value-cell umbrella enumerations ("EXACTLY signal/attr-as-signal/derived/recurrent") ALL gain `deferred T` — it is a value channel inside the cell T umbrella.

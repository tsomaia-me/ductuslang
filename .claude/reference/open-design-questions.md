## Open

- §16's edges, for the batch: which names a region turns into placeholders (the peer's pick: a name nothing outside a region declares, everywhere; for a region inside a body, also every name it writes, within that body and the bodies nested in it, and every path segment under that instance; a region at top level adds nothing, since a second declaration of a declared name is its own fault); which fault of several on one line draws, and whether an opener left open yields to a later fault on its line; whether an unknown unit suffix and the 2¹²⁷ literal are syntax faults with a region (the proposal derives for the suffix, from the colon ruling's second call, a later stage's fault with no region, for the batch to record: its question 6); what a fault on a comment-only line does; what the counts say when a fault's region is empty; which faults still draw beside a limit's stop; how much of a pattern's use stays unexpanded when one argument is a placeholder; which expression is the placeholder for a fault of legality; whether two uses of one undeclared name are one fault or two; how many messages a faulty line draws when a `for`, a pattern or a call reaches it many times.
- Whether a child or wire name equal to a kind's, a pattern's or a type's name is an error, as a name equal to an enum variant is (§6.5). Today it shadows the kind in its body, so `Lamp as Dims` turns an earlier `Dims: wash` in that body into an error. Under the colon ruling it no longer bears on soundness; it is a question of taste for the owner, with the §16 batch.
- What is taken from the old engines' code and tests beyond the syntax, as cases and never as a yardstick (for the syntax it is ruled: Settled, the parser).
- What "keep the IR" keeps: the flat IR draws `unbuilt-construct` for about forty constructs and 25 SPEC examples are listed pending; one id space and one symbol table run across the prelude and every file (`FlatIr::after`, `Symbols::layer`), so file-local ids reshape it at least there; a second, tree-shaped IR (`Hir`) feeds the old engine.
- What the compiler hands its two consumers, the code generator first, the main mode, and the evaluator second. The only statement of either is the last design's, `ARCHITECTURE.md` §3 to §6 and §8 beside the SPEC; core holds a `Program` and no runtime, and no generator exists in the old code. Of that file §7 is still not read: it is the design being replaced and anchors wrongly. With it: §12.5's bit-identical promise now spans two engines, and ARCHITECTURE §8's differential test ("compiles every fixture project both ways and requires equal Programs and equal commit traces") is owed to the loops as a stated test or a gate job; a sentence in §12.5 naming the two engines and their agreement waits until the compiled mode is designed, by the owner's ruling of 2026-11-15 that only settled things go in the SPEC (Settled, Process); and the speed promise gains a second cost in the main mode, the user's `rustc` time over the generated module, measured before N.

- Not yet designed, and on no owed list: a home for the runtime's rules (until it exists `.claude/docs/CODING.md` and `.claude/docs/REVIEWING.md` are kept, fenced; the three rules kept for core were checked against the SPEC on 2026-11-15: no allocation on commit is already §1.1 and §12.6; lock-free hand-off is not in the SPEC, which has no threads and in §12.1 only "the runtime never waiting", and its "refuses when full" fits a channel only, not a stream or a state; integer time has no subject, since §12.2 gives the runtime no clock and time values are seconds as floats; the owner decides at the runtime's design whether the third is kept at all); the runtime's build design (buffers, the commit, the host's hand-off of writes, reload), owed before M3 is built; the code generator's design, the main mode by the ruling of 2026-11-15, with what it needs from the Program, read beside the runtime's sketch so that the Program's shape is fixed by neither consumer alone; before that, a sketch of what the runtime needs from the Program, owed before the open question "what the compiler hands the runtime" is settled, so that the Program's shape is not fixed by the compiler's side alone; the base layer (ids and their width, spans, hashing, message order, the one conversion between integer types); the thin slice itself (what it runs through, and when; it measures a crate a stage, the hash's key and the default layout, and sets the budgets); the interleaved middle and its shared tables; the design page of the compiler's entry, which takes the backstop; the gate on wb2, its jobs, its scripts and the stated-test harness of case files; the message catalogue's style line and model messages; what becomes of the two old engines; which machine and command a builder's loop is timed on for 4.6's row.

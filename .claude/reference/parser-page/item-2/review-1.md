## Findings, most severe first

**F1. Section (2), Place 1: the neutral set is wrong in both directions, and the sentence "an expression has no juxtaposition" is false.** Source: §7.7 `Member ::= Kind Flags? ('as' Name)? DefaultArg? | '(' Placement ')'`, §7.8 `Bundle`, §7.4 "A flag is a single character directly after the kind, with no whitespace", §5.1 `Postfix ::= Primary ('.' Name | '[' Index ']' | '(' Args? ')')*`, and the Settled ruling "placements or attribute entries with no whitespace between them are refused". Known by run: an Earley recogniser over the children reading (`InlineChildren`, adjacency modelled: flags adjacent, every member after the first spaced) and over `Expr`, all tails up to 6 tokens, in `neutral.py`. Of 14,340 children-fitting tails, 324 also fit an expression; 297 of those are outside the set the proposal states. The classes it misses:
- A `*` or `+` flag followed by a member: `Soft: Lamp* wash` is a flagged `Lamp` and a child `wash`, or the product `Lamp * wash`. The proposal says a flag makes the tail children-only.
- A member followed by a spaced parenthesised member or a spaced bundle: `Soft: Lamp (wash)`, `Soft: Lamp [wash]`, `Soft: [a] [b]`, `Soft: Lamp/0.5 (x)`, `Soft: [Lamp (x)]` are two members, or a call / an index on an array literal / a call on a literal. The proposal says two or more members are children-only and "an index or call after the first member" is destination-only; both hold only when the `(` or `[` is adjacent (then the children reading is refused by the ruling), which the proposal never mentions. Adjacency decides the children reading and never the expression reading, so the parser's children pass reads token starts; the proposal lists no such input.
- `Kind/Atom` with a string, a bool or a `to.name` atom (`Lamp/"x"`, `Lamp/true`, `Lamp/to.x`): all fit `Lamp / …` as expressions. The proposal's atom list is "a number, a name, a path or a parenthesised expression".
- `(Kind/Atom)`, `[(Name)]`, `(QualifiedName)`: parenthesised placement or parenthesised expression; bundle of a parenthesised member or array literal of a parenthesised expression.
Every form the proposal does call both-fit does fit both (checked one by one). Consequence: the Settled design-page line says the page names "the neutral forms it hands on (9)"; a catalogue entry or a later-stage rule written from this prose would let the parser decide `Soft: Lamp (wash)` as children, against the colon ruling's second call. The design (run both readings, hand on `Both`) is right; the prose is not.

**F2. Section (2), Place 3: two of the three "type test" rules read a one-form text as the other form.** Source: §5.1 `Conversion ::= ('u8' | 'i32' | 'i64' | 'f32' | 'f64') '(' Expr ')'` (a `Primary`), `RecordLit ::= (Name | QualifiedName) TypeArgs? '{' Fields '}'`, and the ruling "text that fits one form is read as that form". The proposal: "A scalar or `str` type word, a comma in a list, or an item that fits a type alone, make it the type test." Known by run (`neutral.py`, targeted): `x is i32(y)` fits only the value compare (`AltType` has no parentheses), and `x is Pair[i32, bool] {left: 1}` fits only the value compare (a record literal; §3.8 later refuses `is` on records, a type error, not a syntax fault). The notes' own line says "a comma list stays open until a `{` does or does not follow, since `Pair[i32, bool] {…}` is a record literal", and the proposal's own (5) bullet ("at `]`, `{` next makes a `RecordLit`") says so too; (2) contradicts both. The old code already distinguishes `i32` from `i32(` (`parser/expressions.rs:198`, `self.nth(1) != Some(SyntaxKind::LParen)`), so the rewrite would regress it if built from (2). Also missing from the proposal's value-only list: a `{` after the form (`x is Band {}`, `x is Band[4] {}`).

**F3. Sections (2) and (5) contradict each other on a type argument's brace group.** (2): "A type argument … adds … a brace group of neutral entries followed by `[..N]` (`{K: V}[..N]`: §3.10's `MapType` or a `MapLit` sliced), with §5.3's `..` sentence not applying there, since it speaks of `is`." (5): "`{` after `is`, or where a type argument starts: … at `}`, `[` then `..` makes a `MapType`, whose entries must fit types". For `Box[{a: b}[..4]]` one section hands on a neutral node and the other a `MapType`. (2) follows the productions and the ruling; (5) should be scoped to `is`. Reasoned from the quoted text; confirmed by run that `{K: V}[..N]` fits both `Type` and `Expr`. The type-argument neutral set also misses `none` (§3.2 `Base … 'none'` and §5.1 `Primary … 'none'`; §5.3's sentence speaks of `is` only), `(Name)[4]` (§3.2 `'(' Type ')' Dims?` or an index on a group) and nested parentheses; run shows 32 Type sentences of ≤4 tokens that also fit `Expr`, including `none`, `(x)`, `none[4]`.

**F4. Section (5), "settled at the token after the closer": true for `(` and `Name [`, not for `{`.** The brace bullet itself needs `[` and then `..`, two tokens after `}`. No token is read twice (the `..` is the slice's when it is not the type's), so the cost claim stands; the summary sentence should say "at most two tokens". I could not build a program for which the token after a `(` group or a `Name [` list is not enough, given the proposal's scoping of the lambda rule to "where an argument or a `let`'s value starts" (a guard `(a): Valve`, a scrutinee `match (a):`, a `from (a):` and an attribute value `level=(x): …` are all positions where `(…)` followed by `:` is a group, and the rule does not reach them). Two unsaid conditions: the `{`-after-`]` rule applies to the first list after a name only (`xs[0][1] {` is a fault, `RecordLit` takes one `TypeArgs`); and the lambda rule needs the machine to know it stands at an argument or a `let` value, a mode the proposal does not list among the machine's inputs. Reasoned.

**F5. Two things decided as defaults.** (i) Section (3): "the fault stands at … the later of the two tokens at which each reading stopped". The notes list "where the fault stands and what it says when a tail fits neither reading" as owed to the §16 batch (PEER.md, Now, item 2's last line). The answer agrees with §16.3's "first token that continues no production" (each reading's stop token is the first it cannot continue, so both have died at the later one), but it is the batch's to rule, not the page's. (ii) "The views: dropped, not rewritten; nothing downstream of the parser is kept that reads them" and T-A's "the old IR build, that is itself replaced" presume the IR build is replaced. Settled says "The IR is the design pass's to keep, reshape or replace"; Open holds "What 'keep the IR' keeps". If the flat IR or `Hir` is kept, its build reads the views, and T-C's "no view to write" becomes "rewrite the IR build against the new enum", a cost the pick does not carry. Should be conditional or put to the owner. Read.

**F6. T-C leaves out one real cost and one unsettled place.** (a) "each part a named field holding a `NodeId`": a `NodeId` is typed by the column, not by the variant, so `Line.head`, `Entry.value`, `Both.children` can point at any of the ~80 variants; every read of a part is a `match` whose other arms are impossible states, which 1.11 says are "typed away where Rust can type it" or go through the one `internal-error` call, listed per site. Typing them away means id families (`ExprId`, `PlacementId`) or inline structs, which changes the row-size question the proposal defers; leaving them means an `internal` site at every part read. Neither is costed, and the claim "1.8 by construction" rests on it. (b) "1.5 (no diagnostics list beside the tree; a fault is a node)": §16.3 says "A fault of §2.2 to §2.6's rules or of a production is a syntax fault"; a tab, a CR without LF, a BOM, a semicolon, `==`, a stray `^`, a mis-indented line ("Its region holds every following line indented at or deeper than its column") and "A block indented under a line that opens none" have no production and no `Line { head, tail }`; where they sit as nodes, and how the lexer's faults reach the tree, is unsaid, so 1.5 is claimed for the stage while only the grammar's faults have a home. Reasoned from the quoted lines. The other claims hold on reading: 1.1 (one appending writer, a parent column as a later table), 1.6 (a `match` names every variant), 2.2 (no text copy, nodes a token bounded, no hash), 2.4 (ids, no `Box`). T-A and T-B's costs as stated are fair; nothing further is left out of all three beyond the lexer faults' home.

**F7. "Which of them are nodes" misclassifies four productions.** The proposal lists `Base`, `Iterable`, `JsonValue`, `Primary` among productions that "only list alternatives … and make no node". `Base ::= (…) Dims? '?'?` carries dimensions and the option; `Iterable ::= Expr '..' Expr | Expr` holds the range; `JsonValue` holds `'-'? JsonNumber`, a path `(Name | QualifiedName) ('.' Name)*`, `'to' ('.' Name)+` and `'(' Expr ')'`; `Primary` holds `'(' Expr ')'`, `'none'`, `'to'`. Each needs a node variant somewhere. `PatternItem ::= CellDecl | LocalLet` is a pure chooser and is not listed. By my test (every alternative one bare name) the pure choosers are `TopItem`, `Suffix`, `Expr`, `Arg`, `PatternItem`, `TypeArg`, `Kind`, `BodyItem`, `SelfDelimited`, `PackageItem`. The page's table of 134 is what the gate reviewer checks against, so this list matters. Run (`prods.py`) and read.

**F8. Question 4's production is wrong as written.** "`(Name | QualifiedName | 'node' | 'wire') Count?`": `Count ::= Digits ('+' | '..' Digits)? | '..' Digits` is the brace's content; the suffix is `('+' | '*' | '{' Count '}')?`. As written, the SPEC's own `children groups: [Lamp+]*` and `-> ([Lamp{2+}])` (§6.4) are refused. "It changes no program" holds for valid programs; it moves `[[Lamp]]` from a later error (§6.4 "or a bundle `[…]` of one node entry", §7.8 "Wires and bundles are not members") to a syntax fault with a region, a change of what a program draws (3.2), which should be said when it goes to the owner. Read.

**F9. "The old parser's one scan is `group`" is false; the five decisions are right.** `closed_groups` (`mod.rs:498`) runs its own loop over `kind_at` and never calls `group`; `final_colon`, `match_anchor`, `skip_to_final_colon` (`mod.rs:953`–`1018`) are their own line scans; `end_region_before` / `holds_stray_colon` (`mod.rs:425`, `1079`) scan a suspended line to end a bracket. Calling the first two groups "callers" of `group` misdescribes them, and the third is not named (it is recovery §16 replaces, like the others). The five deciding sites check out: `after_group` from `at_lambda` (`lambdas.rs:11`), `type_start` (`types.rs:40`) and `at_alt_type` (`expressions.rs:216`); `group_has_comma` from `type_args_optional` (`types.rs:264`); `group` from `at_record_literal` (`decls.rs:114`), with the callers the table names. "The fifth is the map type": the supervisor's four were "a lambda's start, a type's start, a comma in a group, `{`"; which of the record literal and the map type that `{` meant is not knowable, so the proposal names the missing one by assertion.

# Valid sample programs

Fifteen SymphonyScript programs of rising complexity, written for the language models that generate test programs. Each compiles against the example vocabulary (`docs/SPEC.md` §1.3) on main's compiler with no error, no warning and no `evolve-check` signal. They carry no comments; the table says what each teaches.

Check them with `evolve-check`: build one JSON line per file, `{"id": "<name>", "sources": [{"path": "main.sym", "text": "<program>"}]}`, run `evolve-check <programs.jsonl> <verdicts.jsonl>`, and expect `"parses": true`, an empty `diagnostics` list and an empty `signals` list on every line.

## What the samples respect in the example vocabulary

- Every top-level instance is reached from the `Session` through children or wires, because an unreached one draws a warning (§10.2). `Kit` and top-level `Synth` have no wire that reaches them in the example vocabulary, so no sample uses them; a `Synth` is a child of a `Track`.
- A wire is written inside its source's body, and `Feeds` and `Modulates` leave an `Osc` or `Filter`, so those wires sit inside the `Osc` and `Filter` bodies.
- A gate comes before an attribute clause: `Plays when looping | gain=0.5: bridge`.
- A continued attribute clause starts its continuation lines at the column of its first entry. The line before such a clause holds no declared name, because renaming a name changes the column and `evolve-check` reports the change as a `rename` signal.
- Time-family values reach no attribute of the example vocabulary, so the samples use them as ratios (`250ms / 1s`) and in strings.
- No sample mixes a plain value into a comparison with a family value; `span > 2bars` stands where `span > 2` would be an error.
